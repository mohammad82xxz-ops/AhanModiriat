# چک‌لیست نهایی بررسی دستی و باگ‌گیری آهن‌آلات برادران

این چک‌لیست برای بررسی انسانی برنامه است؛ موارد را فقط بعد از اجرای واقعی علامت بزنید. تست‌های خودکار CI جایگزین این بررسی‌ها نیستند.

## روش ثبت نتیجه

برای هر مورد یکی از وضعیت‌ها را ثبت کنید:
- [ ] انجام نشده
- [x] انجام شد و قبول است
- [!] باگ پیدا شد؛ شماره باگ را در بخش «گزارش باگ» بنویسید
- [~] قابل آزمایش نبود؛ علت را یادداشت کنید

**قبل از شروع:** از نسخهٔ آزمایشی و دیتابیس کپی پشتیبان بگیرید. فقط با دیتابیس آزمایشی کار کنید؛ اطلاعات واقعی کسب‌وکار را در تست وارد نکنید. تاریخ، نسخه/commit، سیستم‌عامل و مرورگر را یادداشت کنید.

## A. نصب و اجرای اولیه در ویندوز

- [ ] فایل/پوشهٔ خروجی Windows OneDir را از [Artifact اجرای CI شمارهٔ 286](https://github.com/mohammad82xxz-ops/AhanModiriat/actions/runs/40907563158/artifacts/12911888706) دریافت و کامل Extract کنید.
- [ ] برنامه از پوشهٔ استخراج‌شده، بدون نصب Python یا ابزار توسعه، اجرا می‌شود.
- [ ] اجرای اول بدون خطای غیرمنتظره، پنجرهٔ خطا یا بسته‌شدن ناگهانی انجام می‌شود.
- [ ] برنامه در مسیر دارای فاصله یا حروف فارسی اجرا می‌شود (در صورت امکان).
- [ ] برنامه بعد از بستن و اجرای دوباره، اطلاعات آزمایشی را حفظ می‌کند.
- [ ] اجرای برنامه از مسیر غیرقابل‌نوشتن، یا خطای دسترسی فایل، پیام قابل‌فهم می‌دهد و بی‌صدا خراب نمی‌شود.
- [ ] دیتابیس آزمایشی و فایل‌های موردنیاز در محل مورد انتظار ساخته می‌شوند؛ دادهٔ موجود بازنویسی یا حذف نمی‌شود.
- [ ] آنتی‌ویروس/Windows SmartScreen و پیام‌های ویندوز ثبت شوند؛ هشدار را بدون بررسی نادیده نگیرید.

## B. مسیر اصلی انبار، خرید، فروش و هزینه

با کالاهای آزمایشی و اعداد مشخص آزمایش کنید و مقدار قبل/بعد را یادداشت کنید.

- [ ] کالای جدید با نام، دسته، واحد، قیمت خرید/فروش و حداقل موجودی معتبر ثبت می‌شود.
- [ ] فیلدهای اجباری خالی، پیام واضح می‌دهند و رکورد ناقص ساخته نمی‌شود.
- [ ] خرید معتبر ثبت می‌شود؛ موجودی، میانگین بهای خرید و گردش نقدی مطابق انتظار تغییر می‌کنند.
- [ ] فروش معتبر ثبت می‌شود؛ موجودی، سود فروش و گردش نقدی درست محاسبه می‌شوند.
- [ ] هزینهٔ روزانه ثبت می‌شود؛ هزینه و ماندهٔ نقدی/سود طبق منطق برنامه به‌روز می‌شوند.
- [ ] شمارش موجودی فیزیکی با موجودی سیستمی متفاوت ثبت می‌شود و تعدیل/سوابق آن درست‌اند.
- [ ] گزارش موجودی، ارزش موجودی، فروش و سود روزانه/ماهانه با تراکنش‌های آزمایشی تطبیق دارد.
- [ ] تاریخ و ترتیب سوابق، فیلترها و جمع کل‌ها درست هستند.
- [ ] پس از خروج و ورود مجدد، مقادیر و گزارش‌ها ثابت می‌مانند.

## C. اعتبارسنجی و ورودی‌های مرزی

برای هر فرم، ورودی نامعتبر را امتحان کنید؛ در صورت امکان بررسی کنید که هیچ رکوردی ذخیره نشده و موجودی/نقدینگی تغییر نکرده است.

- [ ] مقدار اجباری خالی.
- [ ] فقط فاصله در فیلد متنی.
- [ ] عدد صفر در تعداد، قیمت و مبلغ.
- [ ] عدد منفی در تعداد، قیمت و مبلغ.
- [ ] متن یا حروف در فیلد عددی.
- [ ] عدد اعشاری برای تعداد کالا، اگر واحد باید صحیح باشد.
- [ ] عدد بسیار بزرگ و مقدار طولانی‌تر از حد معمول.
- [ ] نام کالای تکراری یا ورودی دارای فاصلهٔ ابتدا/انتها.
- [ ] انتخاب کالا یا طرف حسابی که حذف شده یا دیگر موجود نیست.
- [ ] تاریخ نامعتبر یا تاریخ خارج از محدودهٔ قابل‌قبول.
- [ ] تلاش برای فروش بیشتر از موجودی.
- [ ] فروش بدون قیمت واحد یا بدون تعداد.
- [ ] خرید بدون تعداد یا با تعداد صفر.
- [ ] تلاش برای ارسال دوبارهٔ همان فرم با دوبار کلیک یا فشردن سریع Enter.
- [ ] تازه‌سازی صفحه بعد از ثبت یا استفاده از Back؛ تراکنش دوباره ثبت نمی‌شود.
- [ ] قطع/کندی موقت عملیات یا خطای ذخیره‌سازی، پیام مناسب می‌دهد و داده نیمه‌کاره باقی نمی‌گذارد.

**انتظار اصلی:** درخواست نامعتبر باید رد شود، پیام قابل‌فهم نشان داده شود و هیچ تغییر مالی/انبارداری ناخواسته‌ای ثبت نشود. اگر مشخص نیست یک مقدار از نظر کسب‌وکار باید مجاز باشد یا نه، نتیجه را «نیازمند تصمیم» ثبت کنید و خودسرانه فرض نکنید.

## D. دوباره‌ثبت‌شدن و یکپارچگی داده

- [ ] با دوبار کلیک روی «ثبت»، یک خرید/فروش/هزینهٔ تکراری ناخواسته ساخته نمی‌شود.
- [ ] با تازه‌سازی یا بازگشت به صفحه، ارسال مجدد ناخواسته رخ نمی‌دهد.
- [ ] در صورت خطای عملیات، موجودی تغییر می‌کند اما رکورد تراکنش جا نمی‌ماند (یا برعکس)؛ چنین ناسازگاری نباید رخ دهد.
- [ ] سوابق خرید/فروش/هزینه و دفتر گردش نقدی با هم تطبیق دارند.
- [ ] حذف/ویرایش کالا یا طرف حساب، سوابق قبلی را خراب نمی‌کند.
- [ ] نسخهٔ پشتیبان قابل‌بازیابی است (روی کپی آزمایشی امتحان شود).

## E. رابط کاربری و زبان فارسی

- [ ] متن فارسی راست‌چین و خواناست؛ حروف جداجدا یا مربع نمایش داده نمی‌شوند.
- [ ] اعداد، واحد پول، جداکننده‌های هزارگان و جمع کل‌ها خوانا و یکدست‌اند.
- [ ] در عرض کم پنجره، فرم‌ها، جدول‌ها و دکمه‌ها روی هم نمی‌افتند.
- [ ] جدول عریض قابل پیمایش است و ستون/عملیات ضروری از دسترس خارج نمی‌شود.
- [ ] حالت روشن و تاریک (اگر پشتیبانی می‌شود) کنتراست مناسب دارد.
- [ ] دیالوگ‌ها و پیام‌های موفقیت/خطا قابل‌دیدن‌اند و پشت پنجرهٔ دیگر نمی‌مانند.
- [ ] اسکرین‌شات‌های [ماتریس ۶۸ حالته](https://github.com/mohammad82xxz-ops/AhanModiriat/actions/runs/40907563158/artifacts/12912557336) از نظر بریدگی، هم‌پوشانی و خوانایی فارسی بررسی شدند.

## F. صفحه‌کلید، بزرگ‌نمایی و صفحه‌خوان

- [ ] تمام عملیات اصلی فقط با صفحه‌کلید قابل انجام‌اند.
- [ ] ترتیب Tab منطقی است و نشانگر فوکوس همیشه قابل مشاهده است.
- [ ] هیچ دیالوگ/منو صفحه‌کلید را در خود حبس نمی‌کند؛ بستن و بازگشت فوکوس درست است.
- [ ] بزرگ‌نمایی واقعی مرورگر/ویندوز روی 200٪ محتوا یا عملیات اصلی را حذف نمی‌کند.
- [ ] در اندازهٔ باریک پنجره، عملیات اصلی همچنان در دسترس است.
- [ ] با NVDA یا صفحه‌خوان معادل، عنوان صفحه، تیترها، نام فیلدها، خطاها، پیام موفقیت و سرستون جدول قابل درک‌اند.
- [ ] پیام خطا به فیلد مربوط وصل است و فقط با رنگ مشخص نشده است.

## G. امنیت و خطاهای عملیاتی

- [ ] ورودی‌هایی مانند کوتیشن و متن طولانی به خطای برنامه یا اجرای ناخواسته منجر نمی‌شوند.
- [ ] درخواست نامعتبر/غیرهم‌مبدأ باعث تغییر داده نمی‌شود.
- [ ] خطاهای فایل/دیتابیس پیام قابل‌فهم دارند و اطلاعات حساس در پیام خطا نمایش داده نمی‌شود.
- [ ] برنامه با دیتابیس خالی و دیتابیس آزمایشی دارای سوابق باز می‌شود.
- [ ] بستن ناگهانی و اجرای مجدد باعث خرابی یا حذف داده نمی‌شود (فقط با کپی آزمایشی).

## H. ثبت باگ و نتیجه نهایی

برای هر باگ، این قالب را کپی کنید:

- **شناسه:** BUG-001، BUG-002، ...
- **شدت:** بحرانی / زیاد / متوسط / کم
- **محیط:** ویندوز، نسخه برنامه/commit، اندازه پنجره، حالت روشن/تاریک
- **بخش:** نصب / کالا / خرید / فروش / هزینه / گزارش / دسترس‌پذیری / ...
- **پیش‌شرط و داده آزمایشی:**
- **مراحل بازتولید:** 1. ... 2. ... 3. ...
- **نتیجهٔ مورد انتظار:**
- **نتیجهٔ واقعی:**
- **تکرارپذیری:** همیشه / گاهی / یک بار
- **تصویر یا متن خطا:**
- **آیا داده، موجودی یا مبلغ تغییر اشتباه کرد؟** بله / خیر / نامشخص
